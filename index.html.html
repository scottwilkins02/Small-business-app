How everything is calculated

What each sheet does, where the default numbers come from, and where the honest limits are. Nothing to configure here — just reference.

How the plasterboard numbers are worked out

1. Wall area

Perimeter 2 × (length + width) × ceiling height, minus door/window area (quantity × the sizes set under "Advanced"), gives net wall area.

2. Board layout, not area ÷ board area

The wall run is unwrapped into one continuous strip and tiled with whole boards in both possible orientations — standing tall (fewer horizontal joints) and turned on their side (used when a wall is taller than one board). Whichever needs fewer whole boards is used, the same call a plasterer makes on site.

Openings only remove a whole board where their combined area could plausibly free one up (⌊opening area ÷ board area⌋) — conservative, since offcuts are often reused elsewhere.

3. Ceilings, wastage

An included ceiling is tiled the same way as a flat rectangle. Wastage allowance = net area × wastage %; gross area = net + wastage (a reference figure). The board count itself applies the same wastage % on top of the tiled total, rounded up.

Limits

  • Openings are deducted by area/count only — the diagrams are illustrative, not a cutting plan.
  • Each room is calculated independently; offcuts aren't shared between rooms (the safer assumption for ordering).
How the tile numbers are worked out

1. Which surfaces

Walls are tiled up to the height you set per room (defaults to full ceiling height, but editable for splashbacks/half-height tiling). The floor is optional and tiled separately as a flat rectangle.

2. Layout, both orientations tested

Same approach as boards: the wall run (or floor rectangle) is tiled with the chosen tile size in both orientations, and whichever needs fewer whole tiles is used.

3. Openings capped to the tiled height

Because walls can be tiled to a partial height, a door or window is only deducted up to min(opening height, tiled wall height) — a window entirely above a half-height splashback contributes nothing to the deduction. This is more precise than the plasterboard sheet, where boards always run full height.

4. Boxes

Boxes required = tiles required ÷ tiles per box, rounded up — set "tiles per box" to match what you're actually buying.

Limits

As with boards, opening deductions are area/count-based, not positional, and each room is calculated independently.

How the multi-finish plaster numbers are worked out

Why there's no layout optimisation on this sheet

Multi-finish (skim) plaster is trowelled on wet, not cut to size — there's no board or tile to orient, so unlike the other two sheets this is a straightforward gross area ÷ coverage per bag calculation, rounded up. Applying a tiling algorithm here would be pretending precision that doesn't exist for a wet trowel finish.

Coverage default and sourcing

The default (10 m² per 25 kg bag at 2 mm) is British Gypsum's published figure for Thistle Multi-Finish, confirmed across several independent retailer listings. One retailer FAQ page states "1.5 m² per bag" for the same product, which conflicts with every other source found (including one citing the manufacturer's own product data sheet) and reads as a typo rather than a genuine spec — moderate-to-high confidence the 10 m²/2 mm figure is correct, but check the bag or datasheet for your actual product, since coverage varies by brand and by how heavily you build up the coat.

Thickness scaling

If your application thickness differs from the reference thickness, coverage is scaled proportionally: effective coverage = reference coverage × (reference thickness ÷ your thickness). This is a linear approximation — real coverage vs. thickness isn't perfectly linear at the extremes, so treat it as a reasoned estimate, not a guarantee.

Openings and ceilings

Door/window area is deducted from wall area the same way as the plasterboard sheet (full opening height, since skim is a full-height finish). Ceilings are optional per room, since multi-finish is commonly skimmed onto both.

How the fencing numbers are worked out

Panels and posts

Bays = run length ÷ panel width, rounded up. Posts = bays + 1 for a run standing free at both ends — the standard merchant convention, since a straight run needs a post at each end as well as between every bay — minus one for each end you mark as butting a wall or existing post. Gates aren't included in the bay/post count automatically: each gate replaces one panel bay and adds two extra heavy-duty gate posts on top, since gate posts take more load than a standard line post.

Postcrete

The starting point is roughly 2 bags of 20 kg postcrete per standard 100×100mm timber post, about 1.5 bags for a lighter 75×75mm post, and around 3 bags for a concrete post — figures from UK fencing suppliers' installation guidance, not a single manufacturer spec, so treat them as a reasonable planning estimate rather than an exact figure. Bag count scales with your burial depth relative to a 600mm reference hole (a deeper hole needs more concrete); this scaling is a linear approximation of hole volume, not a precise soil-mechanics calculation. One extra bag per post is added automatically for panel heights of 2 m or more, per the same guidance.

Gravel boards

Optional per run. When included, one gravel board is assumed per panel bay (not under a gate), matching the standard 1.83m gravel board length sold alongside standard panels.

What this sheet doesn't cover

  • Feather-edge / closeboard fencing built from individual boards and arris rails is a different calculation (per-board coverage rather than pre-made panels) and isn't handled here — this sheet assumes pre-made panels.
  • The diagram shows a gate at the end of the run for illustration only — it doesn't know where along the run your gate actually sits.
  • Ground conditions (rock, tree roots, slopes) can change real post-hole depth and concrete use well beyond this estimate.
How the painting numbers are worked out

Why this is coverage-based, not tiled

Like the plaster sheet, paint doesn't come in fixed-size pieces to lay out — so this is net area × coats ÷ coverage per litre, rounded up to whole tins. There's no layout optimisation to do here.

Coverage defaults and sourcing

Trade emulsion (~17 m²/L per coat) is Dulux Trade Vinyl Matt's own technical data sheet. Retail emulsion coverage varies more by brand and colour depth — sources converge on roughly 10-14 m²/L per coat, so 12 m²/L is used as a reasonable mid-point default, not a single authoritative figure. Woodwork gloss/satinwood defaults to 18 m²/L, from Dulux Trade High Gloss's data sheet — moderate-to-high confidence on the trade figures (first-party data sheets), moderate confidence on the retail default (a converged estimate across several installer/calculator sources, not a single spec).

Mist coat

For a room on fresh plaster, ticking "new plaster (add mist coat)" adds one extra coat at the same coverage rate as your topcoats. In practice a mist coat is usually diluted roughly 70:30 with water, which would stretch a litre of neat paint further — but bare plaster also absorbs more paint than a sealed wall, and no technical data sheet found gives a separate coverage figure for a diluted mist coat. Treating it as one additional full-strength coat is a deliberately simple, slightly cautious stand-in rather than a precise figure.

Woodwork/trim

Optional per room: enter linear metres of skirting/architrave and a paintable band height (150mm default, a typical skirting board height) to get a separate gloss/satinwood litre and tin count, priced separately from wall/ceiling emulsion.

Limits

  • Only one tin size is used per material — the app doesn't mix sizes for the cheapest combination (e.g. a 5L + a 1L instead of two 5L). Adjust the tin size setting and compare manually if that matters for your order.
  • Coverage figures assume a reasonably smooth, previously-painted or sealed surface. Textured, bare, or very porous surfaces will use noticeably more paint than these defaults.
How Customers, Quotes and Invoices work

Storage is different on these two sheets

The five calculator sheets save to this browser's local storage. Customers, Quotes and Invoices save to IndexedDB instead — a separate, larger-capacity storage area better suited to records that grow over time. In practice it behaves the same way day-to-day (saves automatically, no button to press), but it's worth knowing they're technically different stores.

One record type, two views

A "quote" and an "invoice" are the same underlying document — converting a quote to an invoice doesn't recreate it from scratch, it duplicates the record, assigns the next invoice number, and switches its type. The original quote is left untouched so your quote history stays intact.

Numbering

Quote and invoice numbers come from counters in Business details that only ever go up — a number is never reused, even if a document is later deleted. This matters: a UK invoice is expected to carry a genuinely unique, sequential number as one of its required elements alongside your business details, the customer's details, a date, and a description of the work.

VAT

If "VAT registered" is off in Business details, no VAT is added to new documents regardless of the rate field. Existing documents keep whatever VAT setting they were created with, so changing your registration status later won't silently rewrite old quotes.

Payments and status

An invoice's status (unpaid / partial / paid) is calculated from its payments log against its total — there's no separate status field to accidentally get out of sync. "Overdue" is shown whenever the due date has passed and a balance remains, calculated live rather than stored.

PDF

"Print / Save as PDF" uses the browser's own print function with a dedicated print layout, rather than a JavaScript PDF library — simpler, nothing to keep working offline, and it uses the same "Print" → "Save to Files" flow already built into iOS.

Limits

  • Deleting a customer doesn't touch existing quotes/invoices for them — each document keeps a snapshot of the customer's details as they were when it was created.
  • Materials library and photo attachments are still queued — not built yet.
How Templates work

A template is just a saved set of line items (and optional notes) with no customer, dates, or VAT attached — those get filled in once you use it. Tapping "Use template" creates a brand new quote, copies the template's lines into it, assigns the next quote number, and takes you to the Quotes/Invoices tab to pick a customer and adjust anything before sending.

Editing or deleting a template afterwards never touches quotes already created from it — same snapshot principle as customers. Templates save to the same IndexedDB store as Customers and Quotes.

How the Price list works

This is a personal reference list only — a place to jot down what you usually pay a merchant, or what you usually charge for a job, so you don't have to remember or dig up an old invoice. It's deliberately not connected to the calculator sheets' cost fields or to quote line items; those stay independent so changing a price here never silently changes a job you've already quoted.

How the Dashboard numbers are worked out

Everything on the Dashboard is computed live from your Quotes and Invoices — nothing is stored separately, so it's always in sync. "Overdue" means an invoice's due date has passed and it still has a balance owing. "Win rate" only counts quotes you've actually acted on (accepted, declined, or converted to an invoice) — a quote just sitting untouched doesn't count against you either way.
